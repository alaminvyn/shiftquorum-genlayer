# Security and limitations

- Each workspace is controlled by its creating wallet. Every write checks ownership, and generation checks the expected input and schedule versions and unique request ID.
- Contract checks apply after consensus. Preference text is serialized as data, and prompt-level guidance supplements deterministic safety checks. An adversarial preference may still influence soft evaluation or make the model fail.
- GenLayer execution can fail or disagree. The application displays transaction state separately from published schedules and reads published schedules using finalized state.
- Use synthetic aliases and avoid names, contact details, addresses, health data, sensitive availability explanations, and confidential information. Input data and transaction calldata are public. Do not insert wallet keys or credentials into project files.
- A zero-eligible-task reason is a deterministic certificate for that input. Other unsuccessful requests can have feasible alternatives. Workload metrics are computed directly. Semantic judgments reflect the contract rubric and validator votes.
